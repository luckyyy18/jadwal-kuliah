# PRD — Sistem Data Jadwal Kuliah (SKPL_05)

> Dokumen ini adalah **sumber kebenaran** untuk pengerjaan kode. Semua implementasi
> di `index.html` + `js/app.js` wajib mengacu ke berkas ini. Jangan menambah fitur
> di luar REQ-01 s.d. REQ-04.

## 1. Ringkasan Produk

Aplikasi web satu halaman untuk **mencatat, menampilkan, memfilter, dan mengubah
data jadwal kuliah**. Dipakai oleh admin jurusan/prodi agar jadwal tidak lagi
tersebar di file Excel.

| Aspek | Keputusan |
|---|---|
| Stack | HTML5, Tailwind CSS (CDN), Vanilla JavaScript (ES6) |
| Database | Supabase (PostgreSQL) — tabel `jadwal_kuliah` |
| Deploy | Vercel (static hosting, tanpa build step) |
| Autentikasi | Tidak ada (sesuai SKPL): akses anon key + RLS |

## 2. Kebutuhan Fungsional

### REQ-01 — Catat Jadwal Baru
Admin mengisi form: **mata kuliah, dosen, hari, jam mulai, jam selesai, ruang, SKS**.
Sistem menyimpan ke tabel `jadwal_kuliah` dan menampilkan baris baru di riwayat.

- Semua kolom `required`.
- `hari` hanya: Senin, Selasa, Rabu, Kamis, Jumat, Sabtu.
- `sks` bilangan bulat 1–6.
- `jam_selesai` harus lebih besar dari `jam_mulai`.
- Sistem **menolak** jadwal yang bentrok (hari sama + ruang sama + rentang jam beririsan).

### REQ-02 — Ringkasan Statistik
Di atas tabel ditampilkan tiga kartu yang dihitung dari data:
1. **Total Jadwal** — jumlah baris.
2. **Total SKS** — `SUM(sks)`.
3. **Hari Terpadat** — hari dengan jumlah jadwal terbanyak.

### REQ-03 — Filter & Pencarian
- Dropdown filter **hari** (Semua + 6 hari).
- Kotak pencarian bebas pada mata kuliah, dosen, dan ruang.
- Filter berjalan di sisi klien; data tetap diambil sekali per aksi CRUD.

### REQ-04 — Edit & Hapus
- Tombol **Edit** mengisi form dengan data baris terpilih; tombol berubah menjadi
  *Simpan Perubahan* + ada tombol *Batal*.
- Tombol **Hapus** menghapus baris setelah konfirmasi.

## 3. Skema Database

```sql
CREATE TABLE public.jadwal_kuliah (
  id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  mata_kuliah  TEXT   NOT NULL CHECK (length(trim(mata_kuliah)) > 0),
  dosen        TEXT   NOT NULL CHECK (length(trim(dosen)) > 0),
  hari         TEXT   NOT NULL CHECK (hari IN ('Senin','Selasa','Rabu','Kamis','Jumat','Sabtu')),
  jam_mulai    TIME   NOT NULL,
  jam_selesai  TIME   NOT NULL,
  ruang        TEXT   NOT NULL CHECK (length(trim(ruang)) > 0),
  sks          SMALLINT NOT NULL CHECK (sks > 0 AND sks <= 6),   -- kunci TC-01
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  CONSTRAINT jam_valid CHECK (jam_selesai > jam_mulai)          -- kunci TC-02
);
```

## 4. Test Case Wajib Panitia

| ID | Skenario | Input | Hasil yang Diharapkan |
|---|---|---|---|
| TC-01 | Tolak SKS tidak valid | `sks = -2` (atau `0`) | Pesan *“SKS harus lebih dari 0”*, tidak ada request POST |
| TC-02 | Tambah jadwal valid | Data lengkap, jam 08:00–09:40, SKS 2 | Baris muncul di riwayat, Total Jadwal +1, Total SKS +2 |
| TC-03 | Tolak jam terbalik | 10:00 → 09:00 | Pesan *“Jam selesai harus lebih besar dari jam mulai”* |
| TC-04 | Tolak bentrok ruang | Ruang & hari sama, jam beririsan | Pesan *“Jadwal bentrok di ruang …”* |
| TC-05 | Anti-XSS | `mata_kuliah = <img src=x onerror=alert('HACKED')>` | Muncul sebagai **teks biasa**, tidak ada pop-up alert |
| TC-06 | Edit & Hapus | Ubah SKS 2 → 3, lalu hapus | Statistik ikut berubah, baris hilang |
